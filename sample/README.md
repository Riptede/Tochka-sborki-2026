# Выборка реальных данных для демо

`sample/raw/` — 810 настоящих карточек из файлов организатора в их исходном формате: `skus.pkl` (YML-фид в
xmltodict), `sku_desc.parquet`, `query_clicks.parquet`. На ней `scripts/demo.py` за ~20 секунд проходит весь путь
решения без 3 ГБ полных данных: сборка БД → каскад → метрики → файл предсказаний → очередь ручной проверки.

| Что | Сколько |
|---|---|
| Офферы с эталоном: смартфоны 150, ноутбуки 120, iPhone 60, телевизоры 60, матрасы 60, чехлы для смартфонов 60, смесители 60 | 570 |
| Карточки без оффера с блоком «ключ: значение» (заголовок начинается со «Смартфон», «Ноутбук», «Телевизор», «Матрас», «Чехол», «Смеситель») | 200 |
| Карточки без оффера, категория которых известна по кликам | 40 |
| Строк кликов (до 20 на карточку) | 7 538 |

Как отбирали: в каждой категории не меньше 50 офферов, поэтому обязательные атрибуты считаются по её собственной
заполненности, как на полных данных. Офферы взяты только с описанием длиннее 100 символов: демо показывает
извлечение из текста. Порядок отбора детерминированный (по md5 от sku_id). Дерево категорий — полное.

Ограничения: выборка смещена к карточкам с текстом и к электронике, а словари строятся только по её train-части
(≈400 офферов). Поэтому метрики демо иллюстративные. Итоговые метрики на полных данных — в `results/`.

Пересобрать из полных данных (нужны `data/raw/`, кэш `data/interim/` и `data/attrex.duckdb`):

```
uv run python scripts/make_sample.py
```
